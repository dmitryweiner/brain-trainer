## 1. До показа пользователям

### 1.1 Мобильная вёрстка

Найдено скриптом `npm run snap` (снимки 390×844, ru и he, см. `shots/`). Горизонтального переполнения и ошибок консоли нет, но:

- **Футер игры.** На узком экране счётчики («Раунд», жизни, «Очки») встают в столбик тремя полосами на всю ширину и съедают треть экрана. Причина: в `OddOneOut.scss` и `ReactionClick.scss` есть глобальный, ничем не ограниченный `.game-stats` с мобильным `flex-direction: column`. Нужно убрать эти глобальные копии и оставить определение в `ui/games/common.scss`: одна строка, перенос только при нехватке места.
- **Шапка.** Название игры с эмодзи переносится на две строки, кнопка «Назад» крупная. Сократить: в шапке иконка и короткое название, либо только «Назад» и счёт.
- **«Найди лишний»** со старыми стилями: поле мельче остальных игр, в футере «Правильно!: 0/0» (ключ `common.correct` с восклицательным знаком). Перевести экран на общие `GameIntro`/`StatusLine`/`square-board`, перенести в `ui/games/` (как и Reaction Click).
- **«0 дн. подряд»** в блоке тренировки при нулевой серии: показывать «Начните серию» или скрывать.
- Проверить на реальном телефоне, особенно жесты: «Обведи линию», «Следи за точкой», свайпы в «Лабиринте», двойные касания в «Кроте».

### 1.2 Надёжность

- **ErrorBoundary** вокруг экрана игры: сейчас ошибка рендера в одной игре роняет всё приложение. Показывать «Что-то пошло не так» и «В меню», писать ошибку в консоль.
- **Напоминание сохранить код синхронизации** после первых сессий (в плане 6.3 «Риски»): без кода прогресс из облака не восстановить.
- **Время тренировок** «0 мин» у пользователей со старой историей: v1 не хранил длительность. Показывать «—» или считать только новые сессии с подписью.

### 1.3 Тексты

## 2. Производительность и чистка

- **Убрать Bootstrap CSS** (план 5.3): ~300 КБ CSS. Найти, какие классы Bootstrap ещё используются (`btn`, `text-muted`, `mb-2`, `text-center`…), заменить своими, удалить зависимость.
- **Разделение кода:** один чанк JS ~520 КБ (Vite предупреждает о чанке больше 500 КБ), CSS ~290 КБ (почти весь — Bootstrap). Загружать экраны игр через `React.lazy` по одному; precache PWA всё равно скачает их для офлайна, но первый запуск на слабом телефоне станет быстрее.
- Перенести Reaction Click и Odd One Out из `components/games/` в `ui/games/`, удалить их отдельные SCSS (см. 1.1).
- `useGameHistory.addGameResult` больше не вызывается играми, только тестами: убрать вместе с v1-формой `GameResult` в адаптерах, когда профиль перейдёт на `sessions`.
- Файлы в корне от прошлой разработки (`STAGE*_COMPLETE.md`, `GAME*_COMPLETE.md`, `prompt*.txt`, `instructions.md`): решить, удалить или перенести в `docs/history/`.
- `localStorage` ограничен ~5 МБ (план 8): при росте истории перейти на IndexedDB за тем же `KeyValueStore`.

## 5. Облако

- Деплой воркера из CI: нужен API-токен Cloudflare в секретах репозитория. Сейчас — вручную, `npm run deploy:cloud` на Node 22. **Порядок важен:** при новых `gameId` сначала воркер, потом приложение, иначе облако отклонит сессии новых игр. Новая версия воркера расходится по сети Cloudflare 20–30 секунд: проверять приём после паузы.
- Мониторинг квот D1 (10 000 новых событий в сутки на сервис, 50 000 на ключ): включить `observability` или простой отчёт по таблице `daily`.

## 7. Тесты и инструменты

- `npm run snap` не входит в CI: можно запускать в Actions на каждом PR и прикладывать снимки артефактом.
- E2E-сценарий в реальном браузере (Playwright) хотя бы на один полный проход игры и синхронизацию с Miniflare-воркером.
- Иногда зависающие тесты: зависший генератор в «Собери фигуру» проявился как висящий vitest. В CI стоит выставить `timeout-minutes` на job.
