# План улучшений Brain Trainer

Дата: 2026-10-05. Статус: в работе. Сделано: этап 0, основная часть этапа 1 (ядро, хранилище v2 с миграцией, `GameShell`, Reaction Click и Odd One Out на движке), этап 1a (облако задеплоено), этап 2 (рейтинги, уровни Odd One Out, экран результатов, карточки, профиль). Дальше: этап 3 (PWA).

## 1. Резюме

Три жалобы пользователей и одно техническое требование:

| Проблема | Что делаем | Этапы |
|---|---|---|
| Задания скучные, не цепляют | Убираем 4 слабые игры, перерабатываем 5, добавляем 10 новых (память, моторика, пространственное мышление). Адаптивная сложность, короткие сессии, «Тренировка дня», стрики, рекорды. | 4, 6 |
| Не видно прогресса по отдельным играм | Новая модель результатов с нормализованным рейтингом 0–1000 и уровнем игры. Карточка игры со спарклайном, экран результатов со сравнением с прошлым разом и рекордом, страница игры в профиле с графиком. | 1, 2 |
| Нельзя играть офлайн, нужен Android | PWA (service worker, manifest) для офлайна в вебе. Capacitor для сборки Android-приложения из того же кода. | 3, 5 |
| Прогресс теряется при смене устройства или очистке браузера | Облачная синхронизация через Cloudflare Worker + D1 по анонимному ключу, локальная копия остаётся для офлайна. | 1, 3a |
| Подготовка к нативному приложению | Разделение на `core` (чистая логика, без браузера), `ui` (React) и `platform` (адаптеры). `core` переносится в React Native без изменений. | 1 |

Принятые продуктовые и технологические решения:

- **Android через Capacitor**, а не React Native. Текущий React/Vite остаётся, ядро изолируется так, чтобы переход на RN позже был возможен без переписывания логики игр и статистики.
- **Радикальная переработка набора игр**: убрать, что не держит внимание, а не «дорабатывать всё».
- **Облако — Cloudflare Worker + D1** (как в `../synesthesia/cloud`), пользователь идентифицируется **анонимным ключом синхронизации**, без регистрации. Локальное хранилище остаётся основным для UI и офлайна, облако — синхронизация и бэкап (раздел 6.3).
- **Деплой через GitHub Actions**: сборка не коммитится в `docs/`, CI проверяет и публикует на Pages.
- **Широкая аудитория**. Допустимы тайм-лимиты, комбо, лайфы. Требования доступности (крупные элементы ≥48px, контраст, без hover) сохраняются, потому что пожилые пользователи остаются важной группой.

## 2. Аудит текущего состояния

Объём: 13 игр, ~8 200 строк TS/TSX без тестов, 39 тестовых файлов, 22 SCSS-файла. Стек: React 18, Vite 7, TypeScript, Bootstrap CSS, react-i18next (en/ru/he/uk), Vitest. Деплой на GitHub Pages: собранный `docs/` коммитится в репозиторий (этап 0 переводит его на GitHub Actions).

### 2.1 Что устроено хорошо

- Каждая игра разделена на хук с логикой и компонент с разметкой. Хуки покрыты тестами.
- Есть i18n на 4 языка с RTL.
- Есть история результатов и профиль с вкладками, то есть фундамент для прогресса уже существует.
- Hash-роутинг даёт прямые ссылки на игры и работает в WebView без сервера.

### 2.2 Структурные проблемы

- **Дублирование шаблона игры.** Все 13 игр реализуют один и тот же цикл `intro → раунды → ResultsModal`. Эффект «записать результат ровно один раз» (`addScore` + `addGameResult` + `scoreAddedRef`) скопирован в каждый компонент в `src/components/games/*/*.tsx`. Выбор игры по id — цепочка условий в `src/App.tsx:115-141`.
- **Логика привязана к браузеру.** Хуки игр напрямую зовут `window.setTimeout`, состояние живёт в `useRef`. Тесты вынуждены крутить фейковые таймеры React. Такой код нельзя перенести в React Native и трудно переиспользовать между играми.
- **Платформенные зависимости размазаны по коду**: `localStorage` в `src/hooks/useLocalStorage.ts`, `window.location.hash` в `src/App.tsx`, `window.confirm` в `src/components/Profile/Profile.tsx`, `document.documentElement.dir` в `src/components/common/Header.tsx`, `i18next-browser-languagedetector` в `src/i18n/index.ts`.
- **Bootstrap не нужен.** `react-bootstrap` в зависимостях, но нигде не импортируется. Из Bootstrap используется только CSS, при этом все компоненты стилизованы собственными SCSS-классами.

### 2.3 Проблемы с результатами и прогрессом

- **«Лучший результат» в меню на самом деле сумма.** `useScore.addScore` накапливает очки (`src/hooks/useScore.ts:40-43`), а `GameMenu` показывает это число как best score (`src/components/GameMenu.tsx:29`). Чем больше играешь, тем больше «рекорд», независимо от качества игры.
- **Шкалы очков несопоставимы.** Reaction Click даёт максимум 25, Memory Flip до 100, Flags до 100, N-Back около 45. Общий счёт и сравнение между играми ничего не значат.
- **История бедная.** `GameResult` хранит только `score`, `accuracy`, `averageTime`, `timestamp` (`src/hooks/useGameHistory.ts:7-18`). Нет достигнутого уровня, размера сетки, длины последовательности. Нет версии схемы, поэтому любая миграция будет болезненной.
- **Тренд примитивный**: среднее последних 5 против предыдущих 5 по score. На карточке игры тренда нет вообще. График в профиле показывает только последние 7 дней и спрятан в раскрывающейся карточке.

### 2.4 Баги

- Пять игр (ReactionClick, ColorTap, SymbolMatch, OddOneOut, HiddenNumber) передают в `GameLayout` проп `footerContent`, а компонент принимает `footer` (`src/components/common/GameLayout.tsx:7`). Футер со счётом и номером раунда у этих игр не отображается.
- Logic Pair Concept: 10 фиксированных раундов с текстами на русском в `src/utils/logicPairData.ts`. В английской, ивритской и украинской версиях задания остаются русскими. Раунды повторяются уже во второй игре.
- `useLocalStorage.setValue` читает `storedValue` из замыкания, поэтому два вызова подряд в одном тике теряют первое обновление.

### 2.5 Офлайн

Service worker и manifest отсутствуют. Приложение статическое и не ходит в сеть после загрузки, поэтому PWA даёт полноценный офлайн почти бесплатно.

## 3. Игры

### 3.1 Принципы «цепляющести»

1. **Адаптивная сложность.** Уровень каждой игры хранится между сессиями. После сессии: точность ≥85% → уровень +1, точность <60% → уровень −1. Игрок всегда на границе своих возможностей, скучно не становится.
2. **Короткая сессия с явным концом.** 60–90 секунд или фиксированное число раундов. В реакционных играх — 3 лайфа и комбо-множитель за серию правильных ответов.
3. **Мгновенная обратная связь.** Звук и вибрация на попадание и ошибку (отключаемые в настройках), короткая анимация, счётчик комбо.
4. **«Тренировка дня».** Набор из 3–4 игр разных категорий, около 5 минут. Выполнил — день засчитан в стрик. Стрик показывается на главном экране.
5. **Рекорды и прогресс.** Экран результатов всегда сравнивает с прошлым разом и с рекордом. «Новый рекорд!» с конфетти и вибрацией. Повышение уровня — отдельное событие.
6. **Достижения.** Небольшой список (первая игра, 7 дней подряд, уровень 10 в любой игре, все категории за день). Без магазинов и валют.

### 3.2 Убрать (4 игры)

| Игра | Почему |
|---|---|
| Color Tap | Зелёный → ДА, красный → НЕТ. Бинарный выбор без прогрессии, надоедает на пятом раунде. Реакцию тренирует «Поймай крота». |
| Symbol Match | Два эмодзи, «одинаковые или нет». Та же бинарность; «сложные» пары зависят от шрифта эмодзи и на Android выглядят иначе. Зрительное различение покрывает Odd One Out. |
| Hidden Number | Поиск одной цифры на поле 5×6, 10 раз подряд. Заменяется таблицей Шульте, которая тренирует то же, но с понятной прогрессией и известным «спортивным» форматом. |
| Logic Pair Concept | 10 захардкоженных раундов на русском, не переведены, повторяются. Чтобы сделать хорошо, нужна большая локализованная база, это отдельный проект. |

История этих игр сохраняется в хранилище (для совместимости и на случай возврата), карточки скрываются из меню, id остаются зарезервированными.

### 3.3 Переработать (5 игр)

- **Sequence Recall → «Повтори»** в духе Simon. Вместо абстрактных эмодзи — 4 крупные цветные панели со своим звуком, на высоких уровнях 6 и 9 панелей. Длина последовательности растёт адаптивно без потолка в 6. Скорость показа ускоряется с уровнем.
- **Phone Recall → «Числовая память».** Прямой и обратный порядок (обратный — классический тест рабочей памяти), адаптивная длина 3…12, показ цифр по одной с темпом, зависящим от уровня.
- **Dual-Rule Reaction → «Переключись».** Добавить Stroop-режим: слово «КРАСНЫЙ», написанное синим, нужно ответить по цвету чернил. Смена правила случайная, с явной подсказкой за секунду до смены на низких уровнях и без неё на высоких. Тайм-лимит на ответ 2 с, лайфы.
- **N-Back.** Адаптивный N от 1 до 3, сессия 90 секунд вместо 3 блоков по 20. Позиционный вариант: вместо эмодзи загорается клетка сетки 3×3, и сравнивать нужно позицию. Эмодзи заменить на цветные фигуры, чтобы не зависеть от шрифта.
- **Reaction Click.** 10 попыток, фальстарт отнимает лайф, серия быстрых реакций даёт комбо. На экране результатов — распределение времён и лучшее время за всё время.

Оставить без изменений механики, добавить только адаптивную сложность и рейтинг: **Memory Flip**, **Odd One Out**, **Emoji Hunt**, **Flags**.

### 3.4 Добавить (10 игр)

Все новые игры рисуются SVG или DOM без картинок, чтобы работать одинаково на вебе, в Capacitor и позднее в React Native (`react-native-svg`).

**Память**

1. **Memory Matrix («Запомни узор»).** На сетке на 1,5 с подсвечиваются K клеток, затем гаснут. Нужно нажать те же. Прогрессия: сетка 3×3 → 6×6, K от 3 до 12, время показа уменьшается. Метрики: K, размер сетки, точность. Рейтинг по максимальному K с точностью ≥80%.
2. **«Что где лежало».** На сетке 2×2…4×4 показываются предметы на 2–4 с, затем прячутся. Вопрос: «Где был 🍎?» → нажать клетку. 8–12 вопросов за сессию. Метрики: число предметов, точность, время ответа.

**Внимание**

3. **Таблица Шульте.** Найти числа 1…25 по порядку на поле 5×5. Уровни: 4×4 → 5×5 → 6×6, затем красно-чёрная таблица (чёрные по возрастанию, красные по убыванию, чередуя). Метрика: время прохождения. Рейтинг по времени для текущего размера.

**Моторика и реакция**

4. **«Поймай крота».** На поле 3×3…4×4 появляются цели на 1,2…0,5 с, нужно успеть нажать. Появляются ложные цели (бомбы), которые нажимать нельзя. 3 лайфа, комбо. Сессия 60 с. Метрики: попадания, промахи, ложные нажатия, среднее время реакции.
5. **«Обведи линию».** Показана кривая (SVG-путь) с коридором. Нужно провести пальцем от начала до конца, не выходя за коридор. Pointer events с `touch-action: none`. Уровни: коридор сужается, кривая усложняется (спирали, зигзаги). Метрики: процент пути внутри коридора, время.
6. **«Следи за точкой».** Цель плавно движется по экрану, нужно удерживать палец на ней. Скорость и непредсказуемость траектории растут. Сессия 30 с. Метрика: процент времени на цели.

**Пространственное мышление**

7. **«Поверни фигуру».** Показана фигура из 4–6 клеток (полимино). Из 4 вариантов выбрать ту же фигуру, повёрнутую на 90/180/270°; остальные варианты — зеркальные копии и другие фигуры. Генерируется процедурно. Уровни: больше клеток, зеркальные дистракторы ближе к правильному. Метрики: точность, время.
8. **«Зеркало».** Обратная задача: выбрать зеркальное отражение фигуры среди поворотов. Тот же генератор, что в игре 7.
9. **«Лабиринт».** Процедурный лабиринт 5×5 → 12×12, шарик ведётся свайпами или перетаскиванием. Таймер. Метрики: время, число лишних ходов.
10. **«Собери фигуру».** Квадрат с вырезанным куском, 4 варианта кусков, один подходит. Куски — полимино с поворотами. Уровни: куски сложнее, дистракторы отличаются одной клеткой.

Порядок реализации: **батч 1** — Memory Matrix, Шульте, Поймай крота, Обведи линию, Поверни фигуру (по одной игре каждой категории). **Батч 2** — остальные пять.

### 3.5 Меню

Группировка карточек по категориям: Память, Внимание, Реакция и моторика, Пространство, Знания (Flags). Сверху — блок «Тренировка дня» со стриком. На карточке — уровень, лучший рейтинг, спарклайн (см. раздел 4).

## 4. Прогресс и результаты

### 4.1 Модель данных v2

```ts
interface GameSession {
  id: string;              // uuid
  gameId: GameId;
  schemaVersion: 2;
  startedAt: number;       // epoch ms
  durationMs: number;
  level: number;           // уровень, на котором играли
  score: number;           // сырые очки игры (как сейчас)
  rating: number;          // 0–1000, нормализован для игры
  accuracy: number;        // 0–100
  avgTimeMs: number;
  metrics: Record<string, number>; // игроспецифичные: bestReactionMs, maxN, gridSize, maxSequence...
}

interface GameProgress {
  gameId: GameId;
  level: number;           // текущий уровень (адаптивная сложность)
  bestRating: number;
  bestMetrics: Record<string, number>;
  sessions: number;
}
```

- У каждой игры есть чистая функция `rating(metrics, level) → 0..1000`. Это делает результаты сравнимыми между сессиями и между играми. Пример для Шульте: `rating = clamp(1000 * (60 с − время) / 60 с)` с поправкой на размер таблицы.
- Агрегаты считаются в `core/stats` без React: лучший, последний, среднее последних 5, тренд как наклон линейной регрессии по последним 10 сессиям, данные для спарклайна, «индекс категории» как среднее лучших рейтингов игр категории.
- Текущий `totalScore` остаётся как «Очки опыта» в шапке. Везде, где сейчас написано «лучший результат», показывается `bestRating`.
- **Рейтинг вычисляется при чтении.** `normalizeSession` в `core/games/registry.ts` пересчитывает рейтинг каждой сессии по текущей формуле игры и приводит её уровень к эффективному (`sessionLevel`): у Odd One Out сессии v1 и этапа 1 без `metrics.rules` считаются сыгранными на уровне 4, это сложность раскладки v1. Поэтому формулы можно настраивать без миграций, а игроки с историей v1 продолжают с соответствующего уровня, не начиная с первого. Поле `rating` в сессии хранит значение, показанное в момент записи.
- **Миграция** из `brain-trainer-results`: каждая старая запись превращается в `GameSession` с `level = 1`, `rating = score / известный максимум игры * 1000`, `metrics = {}`. Хранилище получает ключ версии схемы.
- Существующие функции `getGameStats` и `getGameDailyStats` из `src/hooks/useGameHistory.ts` переносятся в `core/stats` как основа агрегатов.

### 4.2 Экраны

**Карточка игры в меню.** Бейдж уровня («Ур. 7»), лучший рейтинг, последний результат со стрелкой изменения к предыдущему, спарклайн последних 10 сессий. Если игра не играна, вместо статистики — «Попробовать».

**Экран результатов** (полноэкранный, вместо модального окна):

- кольцо с рейтингом сессии и подпись уровня;
- строка сравнения: «+12% к прошлому разу», «Рекорд: 740» или «Новый рекорд!»;
- событие уровня: «Уровень 8 → 9» или «Остаёмся на 8»;
- мини-график последних 10 сессий с выделенной текущей;
- 2–3 ключевые метрики игры словами («Лучшая реакция 212 мс»);
- кнопки «Ещё раз», «Следующая игра», «В меню».

**Профиль.**

- Обзор: индекс по категориям (5 полос), календарь стрика на 4 недели, общее число сессий и время тренировок.
- Страница игры: график рейтинга по сессиям (точки) и по дням (линия), переключатель периода (неделя, месяц, всё), таблица лучших метрик, список последних сессий, текущий уровень и условия следующего.
- Сброс статистики — по одной игре и целиком, с подтверждением через свой диалог, а не `window.confirm`.

## 5. Архитектура

### 5.1 Слои

```
src/
  core/                 чистый TypeScript, нет React-DOM, window, document
    games/<id>/         engine.ts (state machine), generator.ts, rating.ts, tests
    games/registry.ts   GameDefinition[] вместо GAMES_META и if-цепочки в App.tsx
    stats/              агрегаты, тренды, рейтинг по категориям
    storage/            схема, репозитории, миграции v1 → v2
    i18n/               ресурсы переводов (json), без детектора языка
    platform.ts         интерфейсы StorageAdapter, Scheduler, Haptics, Audio, Navigation, LocaleProvider
  ui/                   React-компоненты: GameShell, экраны, карточки, графики
    games/<id>/View.tsx отрисовка состояния движка
  platform/
    web/                localStorage или IndexedDB, Web Audio, navigator.vibrate, hash-роутинг, navigator.language
    capacitor/          Preferences, Haptics, App (аппаратная «Назад»), Device.getLanguageCode
```

Правило: из `core/` нельзя импортировать `react`, `react-dom` и обращаться к глобальным объектам браузера. Проверяется eslint-правилом `no-restricted-imports` и `no-restricted-globals` для папки `core/`.

### 5.2 Движок игры

Каждая игра — детерминированный state machine:

```ts
interface GameEngine<S, E> {
  init(level: number, rng: Rng): S;
  reduce(state: S, event: E, now: number): S;      // события: tap, drag, tick, timeout
  timers(state: S): TimerRequest[];                // какие таймауты нужны в этом состоянии
  isFinished(state: S): boolean;
  result(state: S): Omit<GameSession, 'id' | 'startedAt'>;
}
```

- Реализовано с двумя уточнениями: `reduce(state, event, ctx)` получает `ctx = { now, rng }` (случайность нужна и после `init`, например для задержки следующей попытки), а `GameDefinition` в `core/games/registry.ts` не содержит React-представлений — их добавляет `GameShell` в `ui/` (`GameViews`: Intro, Board, Footer, Details). Игры, ещё не перенесённые на движок, пишут сессии v2 через адаптеры `useGameHistory`/`useScore` с рейтингом по максимуму v1.
- Таймеры запрашиваются декларативно, а запускает их `Scheduler` из платформенного слоя. В тестах — фейковые часы, без React и без `vi.useFakeTimers`.
- `rng` с seed делает раунды воспроизводимыми: тесты и баг-репорты получают один и тот же расклад.
- Один общий хук `useGameEngine(definition)` и один компонент `GameShell` (интро → игра → результаты, запись сессии, обновление уровня) заменяют 13 копий этой логики.
- `GameDefinition { id, category, skills, engine, View, rating, i18nKey, minLevel, maxLevel, sessionKind: 'rounds' | 'timed' }` — единственное место регистрации игры. Меню, роутинг, профиль и «Тренировка дня» читают реестр.

### 5.3 UI-слой

- Убрать `bootstrap` и `react-bootstrap` из зависимостей. Дизайн-токены (цвета, размеры, отступы) — в CSS-переменных в `src/styles/variables.scss`, SCSS остаётся.
- Фигуры, траектории и графики — SVG. Жесты — pointer events с `touch-action: none` на игровой области.
- Роутинг — тонкий адаптер `Navigation` (hash на вебе и в Capacitor, обработка аппаратной кнопки «Назад»).
- i18n: `i18next` остаётся, язык определяется через `LocaleProvider`. Направление текста (RTL) выставляет `ui`, а не компонент шапки.
- Диалоги подтверждения — собственный компонент.

### 5.4 Что это даёт для React Native

`core/` переносится без изменений (там нет DOM). `platform/` заменяется на RN-реализации (AsyncStorage, `react-native-haptic-feedback`, expo-av). `ui/` переписывается на RN-компоненты, причём `View.tsx` каждой игры — это тонкая отрисовка состояния, а не логика. Оценка переноса после этой архитектуры: 3–4 недели, против полного переписывания сейчас.

## 6. Офлайн и Android

### 6.1 PWA

- `vite-plugin-pwa`: manifest (имя, иконки 192/512, `display: standalone`, цвет темы), service worker с precache всех ассетов, `registerType: 'autoUpdate'`. Учесть `base: '/brain-trainer/'` для GitHub Pages.
- Баннер «Доступна новая версия, обновить» и подсказка «Добавить на главный экран».
- Эмодзи рендерятся системным шрифтом: на Android это Noto Color Emoji, и похожие пары в Odd One Out выглядят иначе, чем на iOS/Windows. Проверить наборы на Android; при проблемах заменить критичные наборы на SVG-иконки.
- Деплой: `.github/workflows/deploy.yml` на каждый push и PR запускает lint, `tsc -b`, тесты и сборку, а из `main` публикует `dist/` через `actions/deploy-pages`. В настройках репозитория источник Pages — «GitHub Actions». Сделано на этапе 0.

### 6.2 Capacitor

- Зависимости: `@capacitor/core`, `@capacitor/cli`, `@capacitor/android`. `capacitor.config.ts` с `webDir: 'dist'`.
- Отдельный скрипт `build:app` с `base: './'` (основной `build` собирает `dist/` с базой `/brain-trainer/` для Pages).
- Плагины: `@capacitor/preferences` (хранилище за `StorageAdapter`, при первом запуске импорт из localStorage WebView), `@capacitor/haptics`, `@capacitor/app` (кнопка «Назад» → навигация, а не выход), `@capacitor/status-bar`, `@capacitor/splash-screen`, `@capacitor/screen-orientation` (портрет).

- GitHub Actions: сборка debug-APK по тегу `v*`, артефакт в релизе. Подпись release-сборки — ключ в секретах репозитория.

### 6.3 Облачная синхронизация (Cloudflare)

Устройство остаётся источником истины для UI, облако хранит копию и переносит её между устройствами. Устройство без сети работает как раньше, а при появлении сети отправляет накопленное.

**Инфраструктура** — как в `../synesthesia/cloud`: папка `cloud/` с Worker на TypeScript (сборка esbuild), D1, миграции в `cloud/migrations`, контрактные тесты в Miniflare, `ALLOWED_ORIGINS` для CORS, встроенные rate limits Cloudflare. Деплой воркера — `npm run deploy:cloud` (`wrangler d1 migrations apply --remote && wrangler deploy`), позже можно перенести в CI с токеном в секретах.

**Идентификация — анонимный ключ.** При первом запуске клиент генерирует 120-битный случайный ключ (24 символа Crockford base32, показывается как 6 групп по 4; при вводе O читается как 0, I/L — как 1). Запросы несут `Authorization: Bearer <ключ>`. Сервер хранит только `SHA-256(ключ)`, поэтому утечка базы не даёт доступа к чужим данным. Регистрации и персональных данных нет.

**Модель данных — журнал событий без конфликтов.** В облако уходят только неизменяемые события с клиентским `id` (uuid):

- `session` — завершённая `GameSession` (раздел 4.1);
- `reset` — сброс статистики `{ gameId | null, at }`: сессии с `startedAt < at` для этой игры (или всех игр) не учитываются.

Уровень, рекорды, стрики и прочие агрегаты не синхронизируются, а пересчитываются из журнала в `core/stats`. Слияние двух устройств — объединение множеств событий по `id`, конфликтов не бывает, повторная отправка идемпотентна. Настройки (язык, звук) остаются локальными.

**API воркера:**

- `POST /v1/events` — пачка до 200 событий, тело ≤ 64 КБ, `INSERT OR IGNORE` по `(user, id)` → `{ stored, cursor }`;
- `GET /v1/events?after=<cursor>` — события с серверным порядковым номером больше `cursor`, страницами по 500 → `{ events, cursor, more }`;
- `DELETE /v1/account` — удалить облачную копию ключа (требование Play: пользователь может удалить свои данные; локальные данные остаются, синхронизация выключается);
- `GET /v1/health`.

Схема D1 (`cloud/migrations/0001_initial.sql`): `events(seq AUTOINCREMENT, user, id, kind, body, created, UNIQUE(user, id))`, индекс `(user, seq)`, счётчики `users` и `daily` на триггерах. Квоты: не больше 50 000 событий на ключ (507), не больше 10 000 новых событий в сутки на весь сервис (429, укладывается в бесплатные 100 тыс. записей D1), лимит запросов на IP, валидация тела той же схемой из `core/storage`, что и на клиенте (воркер импортирует её из `../../src/core`, как synesthesia).

**Клиент**: логика в `core/sync/client.ts` (fetch и планировщик передаются снаружи), веб-обвязка — `platform/web/sync.ts` (ключ в localStorage, триггеры `online` и `visibilitychange`), UI — вкладка «Синхронизация» в профиле (`ui/SyncPanel.tsx`):

- локальный репозиторий хранит события и `outbox` неотправленных `id`, а также `cursor` последней загрузки;
- синхронизация при старте, после каждой сессии, по событию `online` и при возврате во вкладку; экспоненциальная задержка при ошибках, таймаут на каждый запрос;
- сначала отправка outbox, потом загрузка новых событий и пересчёт агрегатов;
- при недоступности облака приложение работает полностью локально, в профиле индикатор «синхронизировано / ожидает сети».

**Перенос на другое устройство.** Профиль → «Синхронизация»: показать код и QR со ссылкой `…/#sync=<ключ>`. На втором устройстве ввести код или открыть ссылку: локальные события отправляются под новым ключом, затем загружаются все. Старый ключ на этом устройстве забывается. Кнопка «Создать новый ключ» отвязывает устройство.

**Миграция v1 → v2** выполняется локально (раздел 4.1). Получившиеся сессии попадают в outbox и уходят в облако при первой синхронизации.

## 8. Риски и открытые вопросы

- **Объём хранилища.** localStorage ограничен ~5 МБ; при 20 сессиях в день за год набирается около 7 000 записей (~2 МБ). Достаточно на старте, но `StorageAdapter` должен позволить переехать на IndexedDB или Preferences без изменения `core/`. Облако снимает риск потери данных, но не лимит локального кэша.
- **Потеря ключа синхронизации.** Если пользователь очистил данные и не сохранил код, облачная копия недоступна. Профиль напоминает сохранить код после первых сессий. Восстановления без кода нет (это цена анонимности).
- **Квоты Cloudflare.** Бесплатный D1 — 5 млн чтений и 100 тыс. записей в день. Пачки событий и загрузка по курсору держат запись на уровне «одна сессия — одна строка».
- **Точность таймеров в WebView.** Для реакционных игр использовать `performance.now()`; проверить на слабых Android-устройствах.
- **Эмодзи на Android** выглядят иначе. Критичные наборы (Odd One Out, Emoji Hunt) проверить на устройстве до релиза.
- **Обновление PWA на GitHub Pages.** `autoUpdate` обновляет при следующем открытии; пользователи с «залипшим» service worker — известная проблема, баннер обновления решает её.
- **Перевод новых игр.** 10 новых игр и переработанные экраны добавят около 200 строк в каждый из 4 языков.
